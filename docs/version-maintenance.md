## 日常核对与验证

1. 更新远程引用，确认发布分支、目标提交和工作区状态；有未提交工作时保留它，使用独立工作区开展发布修订。
2. 内容更新后运行 `pnpm stats:update`，把生成的 README 统计与内容改动一起提交。
3. 运行 `pnpm check`、`pnpm build`、`pnpm verify`。README 统计过期、内容校验失败、内部链接失效或构建记录不一致时停止发布并修正。
4. 通过 PR 验证修订；合入 `main` 后，等待发布工作流成功。
5. 获取正式站点部署子路径内的 `/site-version.json`，对照 GitHub Actions 的源码提交，并确认 `workingTreeDirty` 为 false。本地预览记录 true 表示包含未提交修改，不能把该预览当作对应提交的正式构建。

构建记录只包含项目版本、提交、构建时间、工作区是否有修改及内容统计，不包含本地路径、修改文件清单或环境变量。源码归档缺少 Git 时，提交和工作区状态使用 null，避免误报为已核验。

知识层面与词条类型统一在 `src/data/knowledge.ts` 定义，内容校验从同一份定义生成枚举。地图初始及清除选择后的层面数量都从地图数据读取。
